# Siamese

This repository contains the reproducible Siamese source code used in the
manuscript. The SimoLFA Dataset and the trained checkpoint are distributed as
separate Zenodo records because they are too large for the code repository.

Siamese is a dual-branch deep-learning workflow for patch-level classification of SimoLFA images. The released implementation combines an RGB backbone branch with a single-channel reference branch and uses cross-attention modules after ResNet-34 layer3 and layer4.

## Scope

This repository contains the code, fixed SimoLFA image-patch dataset, released checkpoint, and associated training and test results. The public implementation provides the layer3/layer4 AttentionResNet34 configuration and online stochastic augmentation workflow. Reported metrics are patch-level metrics and must not be interpreted as patient-level diagnostic performance.

## Method overview

Each scanner frame is represented by a fixed 5 x 5 patch grid. Every patch is processed by two synchronized inputs: an RGB branch resized to 224 x 224 pixels with the ImageNet-compatible normalization used by the code, and a single-channel reference branch generated by `src/data/preprocess.py`. The backbone is ResNet-34. Cross-attention projects query, key, and value features with 1 x 1 convolutions, computes a spatial similarity matrix, applies softmax normalization, and combines attended reference features with the backbone through a residual connection. A sigmoid probability is thresholded at 0.5 for patch-level classification. For folder-level strip interpretation, the positive-patch proportion threshold is 0.088 (8.8%), calibrated from negative controls.

## Dataset

The release dataset is `data/SimoLFA_Dataset/` with fixed partitions: train 25,168 patches, validation 4,194 patches, and test 4,054 patches, for 33,416 patches in total. The classes are `UT` and `T` with balanced counts in each partition.

Filenames use the form `test-T-00001-block-3-3.png`. Blocks from the same parent source image share the same five-digit source index within a split and class. The authoritative mapping, block coordinates, and SHA-256 checksums are in `data/SimoLFA_Dataset/metadata/filename_manifest_grouped.csv`.

Any redistribution of human-derived or institutionally controlled material remains subject to ethics approval, consent, de-identification, ownership, and repository requirements.

## Installation and quick validation

Create the supplied environment or install the pinned Python dependencies. From the repository root, expose the source tree:

```bash
conda env create -f environment.yml
conda activate siamese-release
pip install -r requirements.txt
export PYTHONPATH=src
python -m unittest discover -s tests -t . -p "test_*.py" -v
```

On Windows PowerShell use `$env:PYTHONPATH = "src"`.

## Training

Training uses online stochastic augmentation. Geometric transformations, Gaussian noise, and contrast adjustment are sampled during training rather than materialized as one fixed augmented dataset. Therefore `results/training/` records one paper-associated training run; new runs may have different epoch-level curves.

Run training with explicit parameters:

```bash
python scripts/train.py --data_root data/SimoLFA_Dataset --save_dir results --epochs 100 --batch_size 32 --lr 1e-4 --pos_weight 2.0 --k 3.0 --seed 42 --deterministic
```

Training records and figures are written to `results/training/`. The script also writes a `weights/` directory beneath the selected save directory. Do not train on the test partition.

## Test-set evaluation

Run `python scripts/evaluate.py --data_root data/SimoLFA_Dataset/test --weights_path model_artifacts/siamese_attention_resnet34_supplementary_checkpoint.pth --output_dir results/test_set_evaluation --batch_size 32 --threshold 0.5 --k 3.0`.

Current test metrics for 4,054 patches are: Accuracy 0.9842, Precision 0.9857, Sensitivity/Recall 0.9827, Specificity 0.9857, F1-score 0.9842, ROC-AUC 0.9984, and Average Precision 0.9986. Summary files are in `results/test_set_evaluation/`; per-patch predictions are in `per_sample_predictions.csv`, and plots and qualitative sample montages are in `figures/`. The 8.8% threshold applies only to folder-level aggregation, not to the 0.5 patch classifier threshold.

## Folder-level inference

Folder-level inference is provided by `scripts/infer.py`. It accepts an authorized folder of original images and writes patch-level, source-image-level, and folder-level CSV outputs. A typical invocation is:

```bash
python scripts/infer.py --project_root . --config configs/release_supplementary_inference.yaml --input_dir /path/to/authorized_images --output_dir results/inference_run --weights_path model_artifacts/siamese_attention_resnet34_supplementary_checkpoint.pth
```

Use `python scripts/infer.py --help` to inspect the exact options for the installed version. Clinical inputs must be handled only under the applicable institutional authorization.

Each original image is divided into a fixed 5 x 5 grid. Generated patches are retained under `<output_dir>/split_images/`. `patch_predictions.csv` records `probability_P` and the resulting P/N label for every patch. The source-image and folder summaries contain `total_patches`, `p_patches`, `n_patches`, `p_patch_ratio`, `n_patch_ratio`, `positive_ratio_threshold`, `is_positive`, and `final_label`. A patch is P when `probability_P > 0.5`; a source image or folder is positive when `p_patch_ratio > 0.088`. No mean, maximum, or minimum probability is used for the aggregate decision.

The source layout is `src/data/`, `src/models/`, `src/preprocessing/`, `src/reproducibility/`, and `src/config.py`. Tests are in `tests/`.

## Output files

Evaluation writes `final_metrics.csv`, `evaluation_report.txt`, `confusion_matrix_counts.csv`, `per_sample_predictions.csv`, and figures under `results/test_set_evaluation/`. Training writes metric histories, `training_log.txt`, and figures under `results/training/`. Inference writes `patch_predictions.csv`, `source_image_predictions.csv`, `folder_predictions.csv`, `detection_report.txt`, provenance records, checksums, and the generated patches under its requested output directory.

## Troubleshooting

- If imports fail, run from the repository root and set `PYTHONPATH=src`.
- If `cv2` or another dependency is missing, install `requirements.txt` or recreate `environment.yml`.
- If a checkpoint fails to load strictly, verify the file name, architecture configuration, and SHA-256 checksum.
- If a data directory is rejected, confirm it contains the required `UT` and `T` subdirectories and that the released partition has not been rearranged.

## Reproducibility and limitations

- Keep the released train, validation, and test partitions fixed when reproducing the reported test result.
- Patch-level metrics do not establish patient-level independence or clinical diagnostic performance.
- Online stochastic augmentation means that new training runs are not expected to reproduce archived curves exactly.
- Exploratory backbone, attention-layer, or static-augmentation comparisons are not claimed to be reproducible unless their code and records are included.
- Follow the data and code availability statements in `docs/` before redistributing data or using restricted clinical material.
